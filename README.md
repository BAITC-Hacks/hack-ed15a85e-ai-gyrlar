# StockPilot

Локальное приложение для расчёта пополнения склада и проверки заказов поставщикам. Решение кейса «Автоматизация формирования заказов поставщикам» для Электрокомплект, HackAlem AI.

Hackathon team repository for AI GYRLAR.

Менеджер получает рекомендации по артикулам, видит формулу и историю спроса, сверяет остаток, корректирует количество и утверждает строку. ИИ-агент использует функции расчёта для объяснения решений и сравнения сценариев. Отправки поставщику нет.

## Быстрый запуск

Откройте **START.cmd**. Приложение откроется по адресу **http://127.0.0.1:8765**. При наличии `data/dataset.json` используются данные партнёра. Этот файл локальный и не переносится при клонировании Git-репозитория.

На другом компьютере нужен Python 3.10 или новее:

```sh
python app.py
```

Если `data/dataset.json` отсутствует, приложение автоматически использует небольшой синтетический набор. Для принудительного демо:

```sh
python app.py --demo --port 8766
```

`START.cmd` использует Python из установленной среды Codex, если он доступен, иначе `py -3`. `launcher.py` запускает сервер в фоне и открывает браузер. Для остановки удобнее запускать `python app.py` в терминале и нажать Ctrl+C. Сервер доступен только на 127.0.0.1. Это приложение для одного пользователя, не публичный production-сервер.

## Загрузка своего Excel или CSV

На главной нажмите **«Выбрать файл»** или перетащите `.xlsx` / `.csv` (до 20 МБ). Есть кнопка скачивания примера CSV, который открывается в Excel.

1. Выберите лист с продажами и проверьте автоматически подобранные столбцы.
2. Для продаж по датам обязательны **код товара, дата, количество**. Для помесячной таблицы — **код товара** и столбцы месяцев (`2026-01`, `Январь 2026`). Первая строка содержит заголовки. Повторная шапка «Количество» и явно подписанные итоги без кода распознаются и исключаются с указанием числа пропущенных строк. Это поддерживает исходные месячные выгрузки IEK и Systeme Electric. Числа с десятичной запятой и текстовые коды с ведущими нулями поддерживаются.
3. При наличии сопоставьте название, поставщика, единицу, свободный остаток, дату остатка, кратность, MOQ, количество в пути, дату поступления и номер накладной. Остаток и поставки должны быть одним актуальным снимком на товар; повторения не суммируются. Противоречащие значения блокируют импорт с номером строки.
4. Укажите дату расчёта и нажмите **«Проанализировать продажи»**. Откроются спрос по товарам, всплески и рекомендации. Нажмите на товар для графика и формулы; ИИ-агент использует этот же набор данных.

Без остатка программа анализирует спрос, но не выдумывает количество заказа. Остаток можно внести в карточке. Без кратности используется предварительная единица; кратность 0 считается неизвестной с предупреждением. Если дата остатка не указана, принимается дата расчёта с предупреждением. При отсутствии даты поступления товар в пути не вычитается из потребности.

Загружается один выбранный лист, без автоматического объединения с другими файлами. Пропуски месяцев внутри периода выгрузки считаются нулевыми продажами: нужна полная история, желательно за 12–24 месяца. Текущий и будущие месяцы исключены из прогноза. Для нового файла сезонность нейтральная; сведения о stockout не предполагаются. Ошибка строки отменяет весь импорт, сохраняя текущий анализ. Лимиты: 250 000 строк, 10 000 товаров, 240 столбцов, 10 листов.

Последний импорт с его параметрами и правками хранится отдельно в `data/uploaded-state.json`. Выбранный набор запоминается в `data/active-dataset.json`. На главной можно переключаться между данными кейса и последней загрузкой. Новый импорт заменяет предыдущий пользовательский набор; исходные данные кейса и их правки сохраняются. Исходный Excel-файл не изменяется. Для `.xlsx` нужен `openpyxl` из `requirements.txt`; CSV работает без него.

## Подключение настоящего ИИ-агента

1. Скопируйте `.env.example` в `.env`.
2. Укажите свой `OPENAI_API_KEY`. Не отправляйте ключ в чат и не включайте его в репозиторий.
3. При необходимости измените `OPENAI_MODEL`. По умолчанию `gpt-5-mini`.
4. Перезапустите сервер. В интерфейсе появится «ИИ подключён».

Используется Responses API с function calling. Модель выбирает функции `inventory_summary`, `find_products`, `explain_product`, `data_quality`, `simulate_scenario`, получает результаты и формирует ответ. Журнал вызовов виден в чате. Функции не изменяют заказ и не отправляют сообщения поставщикам. Сценарный расчёт выполняется на копии параметров.

При подключённом API в OpenAI передаются вопрос, краткая история чата и результаты выбранных функций: сведения о товарах, количества, источники и замечания. Исходные Excel-файлы не загружаются. Установлено `store=false`; это параметр хранения ответа, а не обещание полного отсутствия обработки данных провайдером. Ключ используется только сервером.

Без ключа работает **демо-помощник по заданным сценариям**, а не языковая модель. Он поддерживает срочные позиции, выбросы, качество данных, объяснение по точному артикулу, «Сценарий роста 20%», «Срок поставки 45 дней». Демо-режим явно обозначен. Цикл вызова функций проверен с имитацией транспорта; подключение API дополнительно проверено на синтетических данных.

Официальная документация: [Function calling](https://developers.openai.com/api/docs/guides/function-calling), [GPT-5 mini](https://developers.openai.com/api/docs/models/gpt-5-mini).

## Загрузка предоставленных данных

Установите библиотеку чтения Excel, если её нет:

```sh
python -m pip install -r requirements.txt
```

Можно импортировать два архива напрямую:

На Windows положите `IEK.zip` и `Systeme electric.zip` в «Загрузки» и откройте **IMPORT_DATA.cmd**. Скрипт использует доступный Python; библиотека openpyxl должна быть установлена. Для другой папки: `IMPORT_DATA.cmd "D:\HackAlem\data"`.

```sh
python -X utf8 -m replenishment.importer --archives "C:/Users/User/Downloads/IEK.zip" "C:/Users/User/Downloads/Systeme electric.zip"
```

Либо расположите распакованные каталоги `IEK` и `Systeme electric` внутри одной папки. Вложенные папки из исходных архивов допустимы. В каждом каталоге ожидается шесть файлов: динамика продаж, месячные продажи, месячные остатки, сезонность, товар в пути, MOQ.

```sh
python -m replenishment.importer --source "C:/Users/User/Downloads" --output data/dataset.json
```

Перезапустите приложение после импорта. Описание полей и полноты набора: [data/README.md](data/README.md). Интерфейс показывает источник данных, число товаров и файлов, фильтры поставщика, категории и статуса; экран источников содержит отдельную сводку по каждому поставщику.

Для подтверждённых периодов отсутствия товара используйте CSV по образцу `templates/stockouts.csv`:

```sh
python -m replenishment.importer --source "C:/Users/User/Downloads" --stockouts stockouts.csv
```

Поля: `supplier,code,start,end`. Поставщик — `IEK` либо `Systeme Electric`, даты — `YYYY-MM-DD`, обе границы включены. Пересекающиеся интервалы объединяются. После импорта перезапустите сервер. Источники открываются только для чтения.

Обработанный файл, локальные правки и утверждения исключены из Git. `data/local-state.json` хранит правки и параметры реальных данных, `data/demo-state.json` — отдельное состояние демо. При обновлении импорта ручные остатки сохраняются, но их дата остаётся видимой; менеджеру необходимо сверить их заново.

## Что обнаружено в материалах

Обработаны 12 файлов, 3 908 уникальных пар «поставщик + код 1С» и 248 875 строк расходных накладных. Среди строк 408 отрицательных корректировок. Не включены 9 документов других типов. 21 319 месяцев по SKU сверились с месячными продажами в пределах допуска; у 8 344 имеются расхождения. В файле поставок IEK повторяются 7 кодов; у повторных строк нет количества поставки.

| Источник | Применение |
| --- | --- |
| Месячные продажи обоих поставщиков | Основной объём спроса, пустые значения внутри отчётного периода трактуются как отсутствие движения |
| Динамика продаж | Проверка накладных на разовые всплески и сверка месячных итогов |
| Месячные остатки | История доступности и предварительный остаток на начало сентября |
| Ведомость Systeme Electric | Свободный остаток на 22.09.2026, категории, артикулы, поставка на 24.09; рост из ведомости для сверки |
| Путь IEK | Поступления с датами 30.09, 01.10, 10.10 и 15.10.2026 |
| Сезонность | 12 предоставленных итоговых коэффициентов из L11:L22, нормированных к среднему 1 |
| MOQ | Systeme Electric: кратность. IEK: минимальный разрешённый объём отгрузки, а не кратность |

Ключ — код 1С вместе с поставщиком. Артикулы хранятся строками. Не объединяем товары по похожему названию. Итоговые строки Excel не становятся товарами. Месячные продажи и динамика **не складываются**. Если по коду нет месячной истории, доступные месяцы динамики с 2025 года используются как резервный источник.

Важные ограничения данных:

- Нет ID клиентов. Проверка концентрации одному клиенту реализована в расчётном модуле и проверена на синтетике; на реальных выгрузках доступны только накладные. Номер накладной не считается ID клиента.
- Нет точных интервалов stockout. Пустой или нулевой остаток на начало месяца сам по себе не подтверждает длительность отсутствия. На реальных данных компенсация не выдумывается.
- Для IEK остаток относится к началу сентября. Для части Systeme Electric вне актуальной ведомости также используется месячный снимок. Пустые остатки остаются неизвестными: для таких товаров `qty=null`.
- Сентябрь 2026 неполный и исключён из обучающей истории. Дата сценария фиксирована на 22.09.2026 под этот пакет материалов.
- Сезонность предоставлена на уровне поставщика и рассчитана по денежным продажам. Это приближение для количества по SKU, а не подтверждённая индивидуальная сезонность.
- Условия поставщиков по срокам, цикл заказа и запас не представлены. 30/14/7 дней — редактируемые допущения. Категории SE есть, но нормативов по ним нет; правила категорий задаёт менеджер. Для IEK категория неизвестна.
- В SE есть исторический коэффициент роста. Он показан в карточке для сверки, а не применяется повторно поверх собственного тренда. Внешний прогноз прироста задаётся отдельным параметром.
- Расчёт общий по Алматы. Нет надёжной согласованной разбивки свободных остатков обоих поставщиков по каждому складу.
- Товары с закупкой бухтами и учётом в метрах требуют сверки единиц. Упаковка из имени товара автоматически не извлекается.
- Нет валидированного маппинга импорта в конкретную конфигурацию 1С. CSV содержит код 1С и количества, но готовый обмен с 1С не заявляется.

## Методология

1. **Накладные.** Строки одного товара и документа в один день объединяются. Для минимум восьми положительных наблюдений вычисляются медиана `m` и медиана абсолютных отклонений `MAD`. Если объём больше `max(6m, m + 8 × 1.4826 × MAD)`, он заменяется медианой. При переданном обезличенном ID второй проход проверяет суммарный объём клиента за день. Повторяющиеся большие продажи не удаляются просто из-за своего размера.
2. **Сверка.** Из месячных продаж вычитается только избыток выявленных накладных и только при согласованности динамики с месячным итогом: отклонение не больше `max(1, 5% месячного объёма)`. Иначе месяц остаётся по сводному источнику, расхождение показывается.
3. **Месячный контроль.** Второй консервативный фильтр сравнивает десезонализированный месяц с предыдущими 12 месяцами, требует минимум шесть положительных наблюдений и тот же порог. Он также покрывает историю без подробной динамики. Это эвристика; разовые проекты должны подтверждаться менеджером.
4. **Stockout.** При точных интервалах спрос делится на долю доступных дней, увеличение ограничивается трёхкратным уровнем. Полностью недоступный месяц восстанавливается из медианы доступных месяцев с учётом сезона. Нулевые месяцы без подтверждённого stockout остаются нулевыми.
5. **База.** До 24 полных месяцев используются для истории. Последние максимум 12 после появления ненулевого спроса усредняются с линейными весами от старого к новому. Промежуточные месяцы без продаж сохраняются.
6. **Тренд.** Медиана последних трёх десезонализированных месяцев сравнивается с предыдущими тремя. Изменение должны поддерживать минимум два месяца. Берётся половина относительного изменения с ограничением ±30%. Сценарный прирост менеджера применяется отдельно.
7. **Потребность.** Прогноз разворачивается по календарным дням с коэффициентом соответствующего месяца. Горизонт — срок поставки + цикл пересмотра. Страховой запас равен спросу на следующие заданные дни. Это покрытие в днях, а не статистическая гарантия уровня сервиса.
8. **Поставки.** Учитываются только ожидаемые поступления внутри горизонта, начиная с даты расчёта. Просроченные, слишком поздние и поставки без даты не уменьшают потребность. Отдельная ежедневная проекция выявляет дефицит до поступления: поздняя поставка не устраняет уже возникший дефицит.
9. **Заказ.** `net=max(0, demand+safety−free_stock−eligible_transit)`. При `net>0`: `order=ceil(max(net,minimum)/pack)×pack`. При нулевой потребности минимум не создаёт заказ. Разные единицы не складываются в общий объём.
10. **Утверждение.** Исходная рекомендация и ручное количество различаются. Ноль — допустимая ручная корректировка. Неизвестный/устаревший остаток не позволяет утвердить строку до сверки. Подпись параметров и расчёта снимает старое утверждение при изменениях. Финальное решение локальное, отправки нет.

## Проверка требований

```sh
python -m unittest discover -s tests -v
```

Тесты покрывают влияние остатка и пути, сезонность, рост, категорию, пропуски, stockout, разовый всплеск, раздробленные клиентские продажи, MOQ и кратность, срок поступления, нулевую потребность, ручное утверждение, CSV и цикл ИИ-агента с имитацией API. Синтетический набор демонстрирует аномалии и известный stockout, которых нельзя достоверно разметить в реальных выгрузках.

Это проверка корректности правил, **не оценка точности прогноза на будущем периоде**. Экономия, снижение дефицита и точность ML не измерялись. Для пилота нужны временной backtest без утечки будущих данных, подтверждённые разовые проекты, периоды наличия и актуальные условия поставщиков.

## Сценарий показа на защите

1. Откройте приложение: 12 источников, фильтры IEK / Systeme Electric, общий каталог.
2. Откройте карточку `U733M`: история, исключённые всплески, формула и источники.
3. Спросите агента «Объясни расчёт для U733M». Покажите журнал функции `explain_product`.
4. Спросите «Сценарий роста 20%». Агент сравнит результаты без изменения текущих заказов.
5. В параметрах измените срок поставки или прирост и пересчитайте список.
6. В демо-режиме покажите корректировку и локальное утверждение строки, затем экспорт CSV.
7. На экране источников объясните ограничения реальных данных. Для stockout и ID клиента покажите автоматические тесты и синтетический набор.

## Состав проекта

```text
app.py                       HTTP API, хранение правок, экспорт, контроль утверждения
launcher.py / START.cmd       локальный запуск
replenishment/engine.py       прогноз, выбросы, stockout, расчёт заказа
replenishment/importer.py     адаптеры 12 Excel-файлов, сверка и происхождение
replenishment/agent.py        Responses API, функции, демо-помощник
replenishment/demo.py         синтетические данные
static/                      интерфейс без внешних CDN и npm
tests/                       регрессионные проверки
templates/stockouts.csv       схема подтверждённых интервалов
data/                        локальные данные, исключены из Git
```

Приложение использует стандартную библиотеку Python; для первоначального чтения Excel нужен только openpyxl. Внешний сервис требуется только для подключённой языковой модели. Архив исходников запускается с синтетикой без исходных коммерческих файлов. Для показа на предоставленных данных импортируйте материалы, как описано выше.
